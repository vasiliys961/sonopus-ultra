# Doctor Opus Sono — архитектура

Самостоятельный продукт УЗИ-ассистента. Диагноз формируется внутри Sono. Doctor Opus получает только уже подтверждённый врачом результат и не обязателен для цикла.

## Границы, которые нельзя размывать

Клиническое ядро — чистый TypeScript в `lib/`. В нём нет `window`, React и сетевых вызовов. Браузер, API и будущий нативный клиент подключаются снаружи.

Три разные ответственности не подменяют друг друга:

1. **TechnicalFrameGate** (`QualityScorer`) говорит только о резкости, яркости, движении и заполнении кадра.
2. **OrganModule.guidance** говорит, какой шаг протокола следующий. Это текст протокола, не вывод из резкости.
3. **Brain 1 → Brain 2 → арбитр** формулирует наблюдения и гипотезы. Арбитр — детерминированный код, не ещё одна модель.

Измерение в мм или мл появляется только при подтверждённой шкале: DICOM `PixelSpacing` или явная отметка врача, что числа сняты с калиперов аппарата. Индекс коллапсибельности НПВ безразмерен, поэтому его можно считать по серии в пикселях одной шкалы, но миллиметры при этом не публикуются.

Эллипсоидный объём: `V (мл) = Д × Ш × В × 0.52 / 1000` при размерах в миллиметрах. Коэффициент 0.52 из POCUS-литературы даёт миллилитры, когда размеры в сантиметрах; деление на 1000 переводит мм³ в мл.

Каждый числовой результат несёт `formulaSource: 'published-literature'` и `clinicallyValidated: false`.

## Поток данных

```text
адаптер источника
  → UltrasoundFrame
  → QualityScorer + QualityStreakTracker   (локально, ≥ 10 Гц)
  → автозахват, если score ≥ 0.75 держится ≥ 1.5 с
  → анонимизация пикселей (до любой модели)
  → OrganModule.computeMeasurement
  → Brain 1: Observation[] с evidenceId
  → Brain 2: PreliminaryDiagnosis[]
  → арбитр
  → врач принимает или отклоняет
  → (опционально) POST в Doctor Opus
```

Если качество ниже порога модуля, в модели ничего не уходит. Если не собраны обязательные проекции или врач не подтвердил область, `outcome` становится `insufficient_evidence`, а не «патологии нет».

Повторный вызов модели не затирает решения `operator_accepted` / `operator_rejected`.

## Слои

| Слой | Путь | Роль |
|---|---|---|
| Контракт | `lib/domain` | Кадр, диагноз, калибровка, модуль органа |
| Quality Gate | `lib/quality` | `QualityScorer`, эвристики, серия автозахвата |
| Вход | `lib/device-hub` | UVC/HDMI, захват экрана, синтетический демо-поток, DICOM hot-folder |
| DICOM | `lib/dicom` | `PixelSpacing` → мм/пиксель. Сеть Orthanc не входит в эту версию |
| Приватность | `lib/anonymization` | Маска типичных зон ФИО на кадре |
| Модули | `lib/ultrasound-modules` | Пузырь, НПВ, eFAST, лёгкие, щитовидная железа, ФВ |
| Модели | `lib/llm-pipeline` | Провайдер, разбор JSON, Brain 1 и Brain 2 |
| Арбитр | `lib/diagnostic-arbiter` | Evidence, запрет процентов, полнота протокола |
| Сборка | `lib/pipeline/diagnose.ts` | Единственная оркестрация, её же вызывает API |
| Интерфейс | `app`, `components` | Guided и Second Opinion поверх одного ствола |

`HeuristicQualityScorer` реализует `QualityScorer`. Будущая ML-оценка подключается той же сигнатурой, вызывающий код не переписывается.

## Модули органов

Реестр: `organModuleRegistry`.

| id | Что считает | Шкала |
|---|---|---|
| `bladder` | `0.52 × Д × Ш × В` | мм → мл, иначе `value: undefined` |
| `ivc` | `(Dmax − Dmin) / Dmax` | индекс по серии; мм только при шкале |
| `efast` | 4 бинарные точки, отмечает врач | не пространственная величина |
| `lung` | число B-линий, эвристика столбцов или ввод врача | счётчик, не мм |
| `thyroid` | та же эллипсоидная формула на каждую долю | как у пузыря |
| `cardiac-ef` | `(EDV − ESV) / EDV × 100`, объёмы Симпсоном по контуру | мл и % только при шкале |

Контур для Симпсона требует не меньше 8 точек. Две-три точки сохраняются как ориентиры и не превращаются в объём.

## Что сознательно не сделано

Нативные iOS/Android, обученный `MLQualityScorer`, автоматическая сегментация эндокарда и разбор закрытых протоколов аппаратов не входят в этот код. Для аппаратов без видеовыхода рабочий путь — зеркало USB-C → HDMI → граббер → `getUserMedia`.
